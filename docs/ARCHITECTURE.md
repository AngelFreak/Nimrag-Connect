# Architecture

Current state: phase 0 decoded (night and fresh-pairing captures still open), phase 1 complete (gate 1 passed), stage 2a complete. Plan and status: `IMPLEMENTATION_PLAN.md`.

## Layout

| Path | What | State |
| --- | --- | --- |
| `core/` | `nimrag-core`: sans-IO protocol, capture decoding, FIT decoding/interpretation, parsers (`derive`), protocol client (`client`) | phase 0 decode, phase 1 parsers, stage 2a client done |
| `tools/decode/` | `nimrag-decode`: CLI over `core` (snoop logs, stdin, TCP, `fit` subcommand) | done |
| `tools/proto-recover/` | recovers `.proto` schemas from the app's compiled descriptors | done |
| `tools/fit-profile/` | generator for the local, never-committed FIT profile | done |
| `server/` | `nimrag-server`: axum + sqlx SQLite (WAL); SHA-256 file store with sidecars; device tokens; `POST /api/files`; `reparse`, `rebuild-ledger`, `import-export`; data-dir lock | phase 1 done; JSON read API and auth are phase 3 |
| `docs/protocol/` | protocol map (`PROTOCOL.md`, CSV tables, `proto/`, `HOOKS.md`, `OPEN-QUESTIONS.md`, `PROVENANCE.md`) | done for static analysis + CAP-1..3 |
| `ffi/`, `android/` | UniFFI bindings and the Kotlin app: `engine/` (BLE link, foreground service, companion association, file store, upload worker), `ui/` (Compose screens), `model/AppState.kt` (their contract) | 2b done; 2c–2e built, live test pending |
| `web/` | React frontend | phase 3 |
| `private/` | APKs, decompiled sources, raw captures, notes (git-ignored) | local only |

## `core` modules

All of them are sans-IO: bytes in, values and events out. None of them touches Bluetooth or the network.

| Module | Responsibility |
| --- | --- |
| `crc` | CRC-16/ARC, used by GFDI and FIT |
| `cobs` | COBS encode/decode and a streaming frame splitter |
| `gfdi` | GFDI message parse/encode (plain and compact transaction ids), response body, message names |
| `multilink` | multi-link control frames (handle 0), service ids, request builders |
| `mlr` | MLR 2-byte header, receive window (in-order, duplicate and gap detection) |
| `capture` | btsnoop (file and stream), HCI ACL → L2CAP reassembly, ATT PDUs, UUIDs |
| `link` | `LinkDecoder`: ATT values → multi-link / MLR / COBS / GFDI events; reassembles downloads and parses the directory |
| `describe` | readable summaries of payloads, Garmin time, schema-less protobuf dump |
| `messages` | typed build/parse of the GFDI messages the client and decoder share |
| `client` | sans-IO protocol client (stage 2a): bring-up, MLR, handshake, time, directory, download with CRC, archive only after confirmed storage |
| `fit` | FIT decoder (raw, lossless) and `interpret` (names, scale/offset, components, timestamps) over a locally generated profile |
| `derive` | parsers from interpreted FIT messages to plain rows (activities, monitoring, sleep, HRV, metrics) |

The protocol client (`client`) sits next to `link` and reuses the same codecs and `messages`; the decoder and the client share one implementation of each layer. It passes the phase 0 fixtures by replaying every captured Connect session (`core/tests/client_replay_private.rs`).

## Decisions

| Decision | Reason |
| --- | --- |
| No dependencies in `core` or `tools/decode` (std only) | small attack surface, simple builds for Android later; the formats involved are small and fully specified |
| Hand-written CLI argument parsing | four flags; a dependency isn't worth it |
| Real captures stay in `private/captures/`; tests replay them when present | captures contain personal data (unit id, MACs, notification text, cloud responses). A synthetic session built in the test, with fake ids, is the committed fixture. |
| Unit ids, identity addresses and client ids are never printed by the decoder | so decoder output can be pasted into issues |
| Port Gadgetbridge's Garmin work; project is AGPL-3.0-or-later (owner decision, 2026-11-19) | reuse years of device work instead of decoding every model again; ported code is attributed per file and listed in `docs/PORTED.md`; see `LICENSING.md` |
| Rust toolchain: stable 1.100 via rustup | `rust-version = 1.80` minimum in the workspace |
| Own FIT decoder in `core::fit` instead of the `fitparser` crate (0.12.0, MIT, maintained) | `fitparser` is serde/reader based and cannot write FIT, which phase 4 needs for workout files. Its docs also don't say whether unknown and manufacturer messages are kept. We must keep every message and field raw (hard rules 2 and 3), and `core` stays dependency-free for the Android build. |
| FIT names come from the FIT SDK profile bundled in the Garmin Connect app (`core::fit::profile`, generated by `tools/fit-profile`) | covers the messages the watch actually writes, including ones missing from older public profiles; Gadgetbridge's generated FIT tables are not ported, because they are Garmin profile data (never committed) |
| AI-assisted workflow | Phase 1 onwards: an integrator plans and commits, AI implementers build on separate paths, an independent AI reviewer checks contracts and code before each commit, and the owner makes product decisions. See README, "AI-assisted development". |

Library choices so far (versions pinned; see `server/README.md` for licences):

| Library | Where | Why |
| --- | --- | --- |
| axum 0.8, tokio 1 | server | per the brief; maintained |
| sqlx 0.9 (SQLite, offline `.sqlx` cache committed) | server | compile-time checked queries per the brief |
| sha2, getrandom | server | content addressing, token generation |
| zip 9.6 (deflate only) | server | export import; `enclosed_name` path checks; caps enforced on bytes read |
| own FIT decoder | core | see the decision above |
